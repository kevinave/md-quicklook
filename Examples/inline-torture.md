# 行内解析回归测试

这个文件专门用来暴露手写行内解析器的失效场景。改造前五条全错，改造后应全对。

## 1. 嵌套强调

**粗体里的 *斜体* 应该都生效**

期望：整句加粗，其中「斜体」两字同时倾斜。
旧实现：取到第一个 `**` 就停，里层的星号会原样打出来。

## 2. 行内代码里的星号

`a**b**c` 和 `2 * 3` 都应该原样显示

期望：反引号内一律等宽原文，`**` 不解析。
旧实现：`**` 的判断排在反引号之前，会把代码里的内容当粗体吃掉。

## 3. 转义字符

\*这里不该斜体\* 而且 \*\*这里不该加粗\*\*

期望：显示为 `*这里不该斜体*`，反斜杠本身不显示。
旧实现：完全没有转义处理，反斜杠原样打出来。

## 4. 链接里的方括号

[链接文字[含方括号]](https://example.com) 后面还有正文

期望：整个「链接文字[含方括号]」是一个链接。
旧实现：全文搜索 `](`，嵌套方括号会导致错位。

## 5. 不构成强调的孤立星号

计算式 2 * 3 * 4 = 24，以及 a_b_c 这种下划线

期望：星号和下划线都原样显示，不产生斜体。
旧实现：会把 `* 3 *` 误判成斜体。

## 6. CJK 与标点

中文**粗体**紧贴汉字、中文`行内代码`紧贴汉字，以及全角标点：「引号」、（括号）、破折号——测试。

## 7. 代码块与语法高亮

```swift
let greeting = "hello **world**"   // 这里的星号不该被解析
func f(a: Int) -> Int { a * 2 }
```

```python
def f(x): return x ** 2   # 幂运算的双星号
```
